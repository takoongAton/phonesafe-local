# 대고객 앱 웹뷰용 보안 콘텐츠 생성 프롬프트
> 통합 버전 v4.01_local | 앱 웹뷰 전용 | 900~1,000자 중심 | CSV 기반 | doc 자동 생성 + PDF 추출 + CSV 자동 업데이트

---

## 전제 조건

- 국내 보안뉴스 또는 국내 공공기관의 공식 보안 권고만 참조한다.
- 뉴스 원문을 복사하지 않고 핵심 사실을 재구성하여 작성한다.
- 이전에 생성된 콘텐츠와 동일하거나 유사한 주제는 피한다.
- 개인정보를 프롬프트에 입력하지 않는다.
- 관리자 검수 후 게시하는 것을 원칙으로 한다.
- 본문 마지막에 AI 생성 고지 문구를 반드시 포함한다.

---

## 실행 흐름

```
0단계: 첨부된 magazine_list.csv 읽기 → 기존 카테고리·제목 목록 확인 및 중복 체크
1단계: 실행 요일 확인 → 검색 날짜 범위 결정
2단계: 국내 보안뉴스 수집 (복수 출처)
3단계: 카테고리 분류 및 대표 이슈 1건 선정 (중복 제외)
4단계: 콘텐츠 작성 (900~1,000자)
5단계: doc 파일 자동 생성
5-1단계: PDF 파일 추출 (서론+본문+결론 → 본문으로 통합)
6단계: magazine_list.csv 자동 업데이트
```

---

## 0단계: 기존 콘텐츠 목록 조회 및 중복 확인

### CSV 파일 읽기 방법

프롬프트 실행 시 **`magazine_list.csv` 파일을 첨부**하면 Claude가 해당 파일을 읽어 기존 콘텐츠 목록을 파악한다. 구글 시트 MCP 연결 없이 동작한다.

**CSV 파일 형식:**
```csv
NO,발행일,카테고리,매거진 제목
1,2026-06-04,스미싱/피싱,공공기관 안내처럼 보여도 한 번 더 확인하고 안전하게 이용하세요
2,2026-06-04,해킹/침해사고,비밀번호 자주 바꾸는 것보다 안전하게 관리하는 것이 더 중요합니다.
...
```

**CSV 파일이 없는 경우:**
- 기존 콘텐츠 없음으로 간주하고 진행한다.
- 6단계에서 새 CSV 파일을 자동 생성한다.

### 중복 판단 기준

조회한 목록을 바탕으로 아래 두 가지를 판단한다.

| 구분 | 판단 기준 |
|------|-----------|
| 주제 중복 | 동일한 실제 사건·사고를 다루거나, 핵심 메시지가 80% 이상 유사한 경우 |
| 카테고리 편중 | 동일 카테고리가 최근 3회 이상 연속 선정된 경우 — 다른 카테고리 이슈를 우선 검토 |

### 중복 발생 시 처리

- 중복으로 판단된 이슈는 선정 후보에서 제외하고, 다음 우선순위 이슈로 대체한다.
- 모든 수집 이슈가 기존 콘텐츠와 중복될 경우, 검색 기간을 1주일 더 확장하여 새로운 이슈를 탐색한다.

### 0단계 완료 후 출력 형식

```
[기존 콘텐츠 목록]
· (카테고리) 제목
· (카테고리) 제목
...

[중복 제외 이슈]
· 제외된 이슈 및 사유 (해당 시 기재, 없으면 '해당 없음')

[선정 이슈]
· 최종 선정된 이슈 한 줄 요약
```

## 1단계: 실행 요일별 검색 날짜 범위

| 실행 요일 | 검색 대상 기간 |
|-----------|--------------|
| 화요일 | 직전 주 금요일 ~ 당일 직전 월요일 |
| 금요일 | 당일 주 화요일 ~ 목요일 |
| 그 외 요일 | 사용자에게 "화요일 또는 금요일 기준으로 검색할까요?" 확인 후 진행 |

**실행 당일의 실제 날짜를 먼저 확인한 뒤**, 그 날짜를 기준으로 요일을 판별하여 날짜 범위를 계산한다. 시스템 시계(`date`)나 파일 수정시각(mtime)이 실제와 다를 수 있으므로 그대로 신뢰하지 말고, 오늘 날짜가 불확실하면 진행 전에 사용자에게 확인한다.

## 2단계: 뉴스 수집

### 검색 방법

`web_search` 도구를 사용하여 아래 네 가지 방식을 모두 실행한다.

> **참고:** `site:n.news.naver.com` 쿼리는 네이버의 외부 크롤링 차단 정책으로 인해 실질적인 결과를 반환하지 않는다. 네이버 뉴스는 방식 C의 네이트 뉴스(`site:news.nate.com`)를 통해 대체 수집한다.

**방식 A — 보안 전문 매체 직접 검색 (복수 실행):**

외부 색인이 가능한 국내 보안 전문 매체에 `site:` 연산자를 적용한다.

```
site:boannews.com 해킹 침해사고 [날짜범위]
site:boannews.com 스미싱 피싱 악성코드 [날짜범위]
site:boannews.com 개인정보 유출 [날짜범위]
site:boannews.com 정보보호 정책 권고 [날짜범위]
site:dailysecu.com 해킹 보안 침해 [날짜범위]
site:boho.or.kr 보안공지 [날짜범위]
```

**방식 B — 다음 뉴스 검색 (복수 실행):**

다음 뉴스(`v.daum.net`)는 외부 색인이 가능하므로 `site:` 연산자를 적용한다.

```
site:v.daum.net 사이버보안 해킹 [날짜범위]
site:v.daum.net 스미싱 피싱 악성코드 [날짜범위]
site:v.daum.net 개인정보 유출 침해 [날짜범위]
site:v.daum.net 랜섬웨어 악성앱 [날짜범위]
site:v.daum.net 정보보호 정책 보안공지 [날짜범위]
```

**방식 C — 네이버 뉴스 검색 (복수 실행):**

네이버 뉴스는 `site:n.news.naver.com` 쿼리가 차단되므로, 네이버 뉴스를 색인하는 **네이트 뉴스**(`news.nate.com`)를 통해 대체 수집한다. 네이트 뉴스는 네이버에 제휴된 언론사 기사를 색인하므로 네이버 뉴스와 유사한 결과를 얻을 수 있다.

```
site:news.nate.com 해킹 침해사고 보안 [날짜범위]
site:news.nate.com 스미싱 피싱 악성코드 [날짜범위]
site:news.nate.com 개인정보 유출 침해 [날짜범위]
site:news.nate.com 랜섬웨어 악성앱 [날짜범위]
site:news.nate.com 정보보호 정책 보안 [날짜범위]
```

**방식 D — 키워드 + 날짜 직접 검색 (복수 실행):**

날짜를 키워드에 포함하여 검색한다.

```
국내 해킹 침해사고 [날짜범위] boannews
국내 스미싱 피싱 악성앱 [날짜범위] 보안
개인정보 유출 침해 [날짜범위] KISA
랜섬웨어 악성코드 국내 [날짜범위]
정보보호 보안 권고 [날짜범위] 과기정통부
```

**보조 키워드 (이슈 포착용):**
```
스미싱, 피싱, 큐싱, 보이스피싱
해킹, 침해사고, 사이버공격, APT
개인정보 유출, DB 유출, 다크웹
악성앱, 악성코드, 랜섬웨어, 스파이웨어
KISA, 보호나라, 개인정보보호위원회, 정보보호법
```

### 수집 기준

- 방식 A·B·C·D를 모두 실행하여 최소 5건 이상 기사 수집을 목표로 한다.
- 동일 사건을 다룬 기사는 출처가 달라도 1건으로 묶어서 처리한다.
- 네 방식(보안 전문 매체 / 다음 뉴스 / 네이버 뉴스 / 키워드+날짜)에서 수집한 기사를 통합하여 이슈 후보 목록을 구성한다.
- 아래 신뢰 가능한 출처 2개 이상을 반드시 참고한다.
  - KISA, 보호나라, 개인정보보호위원회, 경찰청, 금융감독원, 과학기술정보통신부, 국내 주요 보안 전문 매체
- 검증 가능한 출처가 부족하거나 사실관계가 불명확한 경우 아래 문구만 출력한다.
  > `검증 가능한 출처 부족`

## 3단계: 카테고리 분류 및 이슈 선정

### 카테고리 정의

| 번호 | 카테고리 | 해당 이슈 |
|------|----------|-----------|
| 1 | 스미싱/피싱 | 문자·이메일·메신저 사기, 가짜 사이트, 큐싱(QR 피싱) |
| 2 | 해킹/침해사고 | 계정 탈취, 랜섬웨어, 서버 침해, APT 공격 |
| 3 | 개인정보 유출 | 개인정보 노출, 대량 유출, 다크웹 유통 |
| 4 | 악성코드/앱 | 위장 앱, 스파이웨어, 트로이목마, 악성 첨부파일 |
| 5 | 제도/정책 | KISA 공지, 보안 법·제도 변경, 취약점 권고 |

위 5개 카테고리에 명확히 해당하지 않으면 콘텐츠를 생성하지 않는다.

### 이슈 선정 기준 (우선순위 순)

1. **비중복성** — 기존 등록 콘텐츠(구글 시트)와 주제·핵심 메시지가 유사하지 않은 이슈를 최우선으로 한다.
2. **파급력** — 피해 규모 또는 피해자 수가 큰 사건
3. **최신성** — 검색 기간 내 가장 최근 발생한 사건
4. **사회적 관심도** — 언론 보도 수가 많은 사건
5. **독자 실용성** — 일반인이 즉시 실천할 수 있는 예방 행동이 있는 사건

## 4단계: 콘텐츠 작성

### 목적

고객의 보안 인식 향상과 피해 예방을 목적으로 한다.
아래 원칙을 반드시 준수한다.

- 특정 기업·기관·서비스의 책임을 단정하지 않는다.
- 확인되지 않은 피해 사실이나 추정 내용을 사실처럼 작성하지 않는다.
- 공포심을 유발하는 표현을 사용하지 않는다.
- 고객이 이해하기 쉬운 안내형 콘텐츠로 작성한다.
- 고객이 실제로 실천할 수 있는 보안 수칙을 반드시 포함한다.

### 작성 스타일

- 존댓말 사용, 반말 금지
- 딱딱한 공지문 형태 지양
- 친근하고 자연스러운 정보성 콘텐츠 형태
- 모바일 화면에서 읽기 쉽도록 짧은 문단 구성
- 전문 용어 최소화 — 필요 시 괄호로 쉬운 설명 병기
  - 예시: `랜섬웨어(파일을 인질로 삼아 돈을 요구하는 악성 프로그램)`

**좋은 예:**
> "최근에는 공공기관을 사칭한 문자로 가짜 사이트에 접속을 유도하는 사례가 꾸준히 발생하고 있습니다."

**나쁜 예:**
> "공격자는 사회공학 기법을 활용하여 악성 URL 접속을 유도하고 인증정보를 탈취한다."

---

### 출력 형식

아래 순서와 형식으로만 출력한다.

---

#### 카테고리
1~5 중 해당 번호와 카테고리명을 표기한다.
예시: `3) 개인정보 유출`

---

#### 제목
고객이 이해하기 쉬운 안내형 제목으로 작성한다.

---

#### 서론
**50~150자**

- 최근 국내 보안 이슈 또는 공식 권고가 있다는 사실만 간략히 전달한다.
- 사건 상세 설명은 하지 않는다.
- 고객이 왜 주의해야 하는지만 안내한다.

예시:
> "최근 공공기관을 사칭한 문자 사례가 확인되고 있어 각별한 주의가 필요합니다."

---

#### 본문
**700~800자**

본문은 **2~4개 단락**으로 구성하며, 소제목 없이 자연스럽게 이어지는 산문 형식으로 작성한다.

---

**단락 구성 원칙**

- 단락 수는 주제의 복잡도에 따라 2~4개 사이에서 자유롭게 구성한다.
- 소제목(▶, ##, **굵은 제목** 등 모든 형태의 소제목)을 사용하지 않는다.
- 각 단락은 자연스럽게 다음 단락으로 이어지도록 작성한다.
- 마지막 단락은 반드시 번호형 행동 가이드(예방 수칙)로 마무리한다.

**단락별 역할 및 권장 분량**

| 단락 | 역할 | 권장 분량 |
|------|------|-----------|
| 단락 1 | 독자 공감 유도 — 생활 밀착형 상황 묘사 | 150~200자 |
| 단락 2 | 피해 가능성과 파급력을 쉽게 설명 | 150~200자 |
| 단락 3 | (선택) 수법을 쉽게 풀어서 설명 (기술 용어 최소화) | 100~150자 |
| 마지막 단락 | 번호형 행동 가이드 (필수) | 250~300자 |

단락 2~3은 주제에 따라 통합하거나 생략할 수 있다.
단, **단락 1(상황 설명)** 과 **마지막 단락(행동 가이드)** 은 항상 포함한다.

---

**행동 가이드 단락 작성 규칙**

- 번호형(1~4번) 4개 항목으로 구성한다.
- 각 항목은 1~2문장, 항목당 60~80자 내외로 작성한다.
- 고객이 5초 안에 핵심 행동을 파악할 수 있도록 작성한다.
- 체크리스트처럼 읽히도록 작성한다.
- 불필요한 배경 설명, 기술 용어 나열 금지

아래 예방 행동 중 상황에 맞는 항목을 포함한다.
```
링크를 바로 누르지 않기
공식 앱 또는 공식 홈페이지에서 직접 확인하기
비밀번호 변경하기
2단계 인증 설정하기
보안 업데이트 적용하기
앱 설치 전 권한 확인하기
의심스러운 요청은 한 번 더 확인하기
로그인 기록 확인하기
사용하지 않는 앱 삭제하기
```

---

**작성 예시 (스미싱/피싱 주제, 3단락 구성)**

```
택배 배송 안내, 공공기관 고지문, 지인의 연락처럼 보이는 문자나
메신저 메시지가 늘어나고 있습니다. 링크를 누르면 개인정보를 입력하는
가짜 사이트로 연결되거나, 스마트폰에 악성 앱이 설치될 수 있습니다.
```

## 5단계: doc 파일 자동 생성

4단계 콘텐츠 작성 완료 후 반드시 아래 절차로 Word 파일을 자동 생성한다.

### 파일명 규칙

```
보안콘텐츠_YYYYMMDD.docx
예) 보안콘텐츠_20260616.docx
```

날짜는 **실행 당일의 실제 날짜를 먼저 확인한 뒤** 적용한다. 시스템 시계(`date`)·파일 mtime을 그대로 신뢰하지 말고, 불확실하면 사용자에게 오늘 날짜를 확인한다. 확정한 날짜를 폴더명·파일명·문서 부제·CSV 발행일에 일관되게 사용한다.

### 문서 구성

| 항목 | 내용 |
|------|------|
| 문서 제목 | 보안 매거진 콘텐츠 |
| 부제 | 실행 날짜 + 프롬프트 버전(v3.72) |
| 카테고리 | 4단계 산출물 반영 |
| 제목 | 4단계 산출물 반영 |
| 서론 | 4단계 산출물 반영 |
| 본문 | 4단계 산출물 반영 (단락 구분 유지) |
| 행동 가이드 | 번호형 목록 (1. 2. 3. 4.) |
| 결론 | 4단계 산출물 반영 |
| AI 고지 문구 | 구분선 아래 이탤릭 소자 |

## 5-1단계: PDF 파일 추출

5단계 doc 생성 완료 후 아래 절차로 PDF를 추출한다.

### PDF 구성 규칙

doc 파일과 달리 PDF는 **서론·본문·결론을 하나의 본문으로 통합**하여 구성한다. 섹션 구분 라벨(서론/본문/결론) 없이 자연스럽게 이어지는 단일 텍스트 흐름으로 작성한다.

| doc 구성 | PDF 구성 |
|----------|----------|
| 카테고리 | 카테고리 |
| 제목 | 제목 |
| 서론 (라벨 포함) | _(통합 본문에 포함)_ |
| 본문 (라벨 포함) | **본문** (서론+본문+결론 통합, 라벨 없음) |
| 결론 (라벨 포함) | _(통합 본문에 포함)_ |
| AI 고지 문구 | AI 고지 문구 |

### 파일명 규칙

```
보안콘텐츠_YYYYMMDD.pdf
예) 보안콘텐츠_20260617.pdf
```

### 생성 코드 (Claude가 bash_tool로 실행)

```python
from reportlab.lib.pagesizes import A4
from reportlab.lib.styles import ParagraphStyle
from reportlab.lib.units import mm
from reportlab.platypus import SimpleDocTemplate, Paragraph, Spacer, HRFlowable
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.ttfonts import TTFont

pdfmetrics.registerFont(TTFont("NanumGothic", "/usr/share/fonts/truetype/nanum/NanumGothic.ttf"))
pdfmetrics.registerFont(TTFont("NanumGothicBold", "/usr/share/fonts/truetype/nanum/NanumGothicBold.ttf"))

TODAY = "[실행 날짜 YYYYMMDD]"
FILENAME = f"보안콘텐츠_{TODAY}.pdf"

doc = SimpleDocTemplate(
    f"/home/claude/{FILENAME}",
    pagesize=A4,
    leftMargin=25*mm, rightMargin=25*mm,
    topMargin=25*mm, bottomMargin=25*mm
)

style_category = ParagraphStyle("category", fontName="NanumGothic",     fontSize=10, textColor="#7C6FE0")
style_title    = ParagraphStyle("title",    fontName="NanumGothicBold", fontSize=16, leading=22, spaceAfter=8)
style_body     = ParagraphStyle("body",     fontName="NanumGothic",     fontSize=10, leading=18, spaceAfter=6)
style_guide    = ParagraphStyle("guide",    fontName="NanumGothic",     fontSize=10, leading=18, leftIndent=12)
style_notice   = ParagraphStyle("notice",   fontName="NanumGothic",     fontSize=8,  textColor="#888888")

story = [
    Paragraph("[카테고리]", style_category),
    Spacer(1, 4*mm),
    Paragraph("[제목]", style_title),
    HRFlowable(width="100%", thickness=1, color="#DDDDDD", spaceAfter=6),
    Paragraph("[서론 텍스트]", style_body),
    Spacer(1, 3*mm),
    Paragraph("[본문 단락1 텍스트]", style_body),
    Spacer(1, 3*mm),
    Paragraph("[본문 단락2 텍스트]", style_body),
    Spacer(1, 3*mm),
    Paragraph("1. [행동 가이드 1]", style_guide),
    Paragraph("2. [행동 가이드 2]", style_guide),
    Paragraph("3. [행동 가이드 3]", style_guide),
    Paragraph("4. [행동 가이드 4]", style_guide),
    Spacer(1, 3*mm),
    Paragraph("[결론 텍스트]", style_body),
    Spacer(1, 6*mm),
    HRFlowable(width="100%", thickness=0.5, color="#CCCCCC", spaceAfter=4),
    Paragraph("※ 본 콘텐츠는 국내 보안뉴스 및 공개된 보안 권고를 참고하여 생성형 AI를 활용해 작성되었으며, 관리자 검수 후 게시되었습니다.", style_notice),
]

doc.build(story)
print(f"PDF 생성 완료: {FILENAME}")
```

1. `/mnt/user-data/outputs/` 폴더로 복사
2. `present_files`로 다운로드 링크 제공

5단계 doc 파일 생성 완료 후 Claude가 `bash_tool`로 아래 코드를 실행하여 `magazine_list.csv`에 새 행을 자동 추가한다.

### 업데이트 코드 (Claude가 실행)

```python
import csv, os
from datetime import date

CSV_PATH = "/mnt/user-data/uploads/magazine_list.csv"
OUT_PATH = "/mnt/user-data/outputs/magazine_list.csv"

TODAY    = date.today().isoformat()      # 예) 2026-06-16
CATEGORY = "[4단계 카테고리]"             # 예) 악성코드/앱
TITLE    = "[4단계 제목]"                 # 예) 마이크로소프트 보안 안내처럼...

# 기존 파일 읽기 (없으면 빈 목록으로 시작)
rows = []
if os.path.exists(CSV_PATH):
    with open(CSV_PATH, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        rows = list(reader)

# 새 행 추가
next_no = len(rows) + 1
rows.append({
    "NO": next_no,
    "발행일": TODAY,
    "카테고리": CATEGORY,
    "매거진 제목": TITLE
})

# 출력 폴더에 저장
with open(OUT_PATH, "w", encoding="utf-8-sig", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["NO","발행일","카테고리","매거진 제목"])
    writer.writeheader()
    writer.writerows(rows)

print(f"CSV 업데이트 완료: {next_no}건 → {OUT_PATH}")
```
