# 매거진 프롬프트 — 작업 가이드

휴대폰안심(PhoneSafe) 앱 웹뷰에 게시하는 **대고객 보안 매거진**을 만드는 폴더다.
이 파일은 `매거진 프롬프트/` 안의 작업에만 적용한다. 앱·홈페이지·가입창 등 다른 폴더 작업에는 쓰지 않는다.

## 기본 규칙

- 대화·설명·산출물은 모두 **한글**, 존댓말(콘텐츠) 기준으로 한다.
- **날짜는 실행 당일의 실제 날짜를 먼저 확인**한 뒤 쓴다. `date`·파일 mtime을 그대로 믿지 말고, 불확실하면 사용자에게 묻는다. 확정한 날짜는 폴더명(`YYMMDD`)·파일명(`YYYYMMDD`)·docx 부제·CSV 발행일에 똑같이 쓴다.
- 콘텐츠는 **관리자 검수 후 게시**하는 것이 원칙이다. 산출물은 초안이며, 게시 전 검수가 필요하다고 보고한다.
- 폴더 안 파일을 임의로 지우거나 덮어쓰지 않는다. 산출 폴더는 항상 새로 만든다.

## 폴더 구조

| 경로 | 역할 |
|------|------|
| `magazine_list.csv` | **마스터 이력 CSV.** 중복 확인의 기준이며 하나만 계속 갱신한다 (UTF-8 BOM, 7열) |
| `매거진 컨텐츠/YYMMDD/` | 실행 1회당 산출 폴더. 같은 날 재실행 시 `YYMMDD_2`, `_3` … 로 자동 증가 |
| `보안콘텐츠_프롬프트_v4.01_local.md` | **현행** 콘텐츠 프롬프트 (로컬 CSV 방식) |
| `보안콘텐츠_프롬프트_v4.00.md` | 구버전 (구글 시트 방식). 보관용, 사용하지 않는다 |
| `배너이미지생성_프롬프트_v1.2.md` | 구버전 배너 프롬프트(720×405, 단일). **현행 규격은 배너 스킬을 따른다** |
| `../.claude/skills/phonesafe-security-magazine/` | 콘텐츠 생성 스킬 (현행 기준 문서) |
| `../.claude/skills/phonesafe-magazine-banner/` | 배너 생성 스킬 (현행 기준 문서) |

프롬프트 문서와 스킬 내용이 다르면 **스킬을 우선**한다.

## 콘텐츠 생성 워크플로우

요청이 "매거진 만들어줘", "보안 콘텐츠 생성" 등이면 `phonesafe-security-magazine` 스킬을 사용한다.

1. **환경 확인**: `python-docx`, `reportlab`, `cairosvg`, `pillow` 가 없으면 스킬의 `scripts/setup.sh` 를 실행한다.
2. **중복 확인**: `magazine_list.csv` 의 카테고리·제목을 읽는다.
   - 주제 중복: 같은 사건이거나 핵심 메시지 80% 이상 유사하면 제외
   - 카테고리 편중: 같은 카테고리가 최근 3회 연속이면 다른 카테고리 우선
3. **검색 범위**: 실행 요일 기준
   - 화요일 → 직전 주 금요일 ~ 직전 월요일
   - 금요일 → 당일 주 화요일 ~ 목요일
   - 그 외 요일 → 어느 기준인지 사용자에게 확인. 가까운 쪽의 범위를 제안할 수 있다
4. **뉴스 수집**: `references/news-collection.md` 의 4가지 방식으로 최소 5건. 신뢰 출처(KISA·보호나라·개인정보위·경찰청·금감원·과기정통부·주요 보안 매체) 2곳 이상 참고. 출처가 부족하면 `검증 가능한 출처 부족` 만 출력하고 중단한다.
5. **이슈 1건 선정**: 비중복성 → 파급력 → 최신성 → 사회적 관심도 → 독자 실용성 순.
6. **작성**: `references/content-guidelines.md` 를 따른다 (아래 요약 참고). `content.json` 으로 저장한다.
7. **산출**: `scripts/generate.py` 로 docx·pdf 생성 + CSV 갱신 + 스냅샷 저장.
8. **배너**: 요청이 있으면 `phonesafe-magazine-banner` 스킬로 **같은 산출 폴더**에 저장한다.

0~3단계가 끝나면 `[기존 콘텐츠 목록] / [중복 제외 이슈] / [선정 이슈]` 형식으로 먼저 보고한다.

## 콘텐츠 규격 (요약)

- 카테고리 5종: `1) 스미싱/피싱` `2) 해킹/침해사고` `3) 개인정보 유출` `4) 악성코드/앱` `5) 제도/정책`
- 전체 **900~1,000자**: 서론 50~150 / 본문 700~800 / 결론 50~100
- 본문은 소제목 없는 2~4단락. 첫 단락은 생활 상황 묘사, 마지막 단락은 **번호형 행동 가이드 4개**(항목당 60~80자)
- 제목은 안내형 문구. 존댓말, 짧은 문단, 전문용어는 괄호로 쉬운 설명 병기
- 본문 끝에 AI 고지 문구 **고정**:
  `※ 본 콘텐츠는 국내 보안뉴스 및 공개된 보안 권고를 참고하여 생성형 AI를 활용해 작성되었으며, 관리자 검수 후 게시되었습니다.`

### 금지 사항

- 기사 원문·제목 복사, 문장 구조 재현 (사실만 재구성)
- 실제 악성 URL, 공격 절차·우회 방법, 전화번호·이메일·계좌번호 등 개인정보
- 피해 규모·공격 주체·특정 기업/기관 책임 단정, 공포심 유발 표현
- 출처 목록, 작성 기준일, 내부 검수 메모를 본문에 넣는 것

## 기존 콘텐츠에서 확인된 패턴

- 행동 가이드 4개는 대체로 **링크 누르지 않기 → 공식 앱/사이트에서 직접 확인 → 계정·설정 점검 → 신고·공유(118 등)** 흐름이다.
- 제목은 "~하세요 / ~해 주세요 / ~확인해 보세요" 로 끝나는 권유형이 대부분이다.
- 시의성(명절, 신규 제도, 최신 수법)을 반영하되 공포를 키우지 않는다.
- 신고·상담 창구는 실제 존재하는 번호만 쓴다 (예: 118 불법스팸대응센터, 1394 보이스피싱, 지급정지는 금융사).
- 태그(`핵심 키워드`)는 5~6개, 비고에는 참고한 기사·기관 URL을 `; ` 로 이어 적는다.

## magazine_list.csv 규칙

- 열: `NO, 발행일, 카테고리, 매거진 제목, 핵심 키워드 (태그), 상태, 비고 / 뉴스 링크`
- `발행일` 은 `YYYY-MM-DD`, `카테고리` 는 번호 없이 이름만 (`스미싱/피싱`), `상태` 는 `작성 완료`
- 인코딩은 **UTF-8 with BOM**. `generate.py` 가 처리하므로 직접 편집할 일이 있으면 BOM을 유지한다
- 1~7번은 초기 작성분이라 태그·상태가 비어 있다. 새 행과 형식이 달라도 고치지 않는다

## 배너 (요약)

- 현행 규격: **1672×941px, 16:9**, 투명 픽셀 0개의 RGB PNG, 스타일 **A~E 5종 모두** 생성
- 파일명: `휴대폰안심_매거진_배너_YYYYMMDD_스타일A.png` … `_스타일E.png`
- 이미지 우측 하단에 `* AI로 생성되었습니다.` 표기, 한글 폰트는 NanumGothic 계열
- 새 배너는 기존 발행 배너(`매거진 컨텐츠/*/*.png`)를 먼저 열어 하우스 스타일을 확인한 뒤 만든다
- 세부 절차는 `phonesafe-magazine-banner` 스킬 문서를 따른다
- **스타일 D의 `No.` 번호는 발행 순서대로 1씩 증가**한다 (260917=106, 260922=107, 260922_2=108, 260930=109, 261008=110). 다음 발행은 111이며, 바코드 문구는 `0 YYMMDD 999999` 형식이다
- 발행된 배너의 SVG 원본은 저장소에 없다. 새로 만들 때는 직전 폴더의 PNG를 열어 구도를 맞춘다
- **cairo 미설치 환경**(Homebrew 없음): `svg_to_png.py` 가 `cairosvg` 를 불러오지 못한다. 이 경우 Chrome 헤드리스(`--headless=new --screenshot`)로 SVG를 렌더한 뒤 PIL로 RGB 합성·1672×941 크롭을 적용해 같은 보장(투명 픽셀 0개)을 맞춘다. 스타일 접미사(`_스타일A`~`E`)는 스크립트가 붙이지 않으므로 직접 붙인다

## 알려진 불일치 (정리 전까지 주의)

- `배너이미지생성_프롬프트_v1.2.md` 는 720×405 단일 스타일이고 "v3.7_final" 을 가리킨다. 현행 스킬(1672×941, 5종)과 다르다.
- `보안콘텐츠_프롬프트_v4.01_local.md` 의 CSV 예시는 4열이지만 실제 CSV는 7열이다.
- 생성 스크립트의 docx 부제에 `v4.01_local` 이 고정 문구로 들어 있다.
